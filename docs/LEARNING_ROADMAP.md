# Roadmap изучения OpenXRay: от простого к сложному

> **Для кого:** Сеньор React разработчик, изучающий C++ через игровой движок  
> **Цель:** Систематическое изучение всех архитектурных фич проекта

---

## 📋 Уровень 0: Подготовка (базовые концепции C++)

**Сложность:** ⭐  
**Время:** 1-2 дня  
**Цель:** Понять базовые паттерны, используемые в проекте

### 0.1. Управление памятью (Memory Management)
- [ ] **xrMemory** — кастомный аллокатор памяти
  - Файлы: `src/xrCore/xrMemory.h`, `src/xrCore/xrMemory.cpp`
  - Что изучить: `xr_new`, `xr_delete`, `mem_alloc`, `mem_free`
  - Аналогия: как `malloc/free`, но с кастомной логикой
  - Зачем: контроль над выделением памяти, оптимизация

- [ ] **Умные указатели** (Smart Pointers)
  - Файлы: `src/xrCommon/xr_smart_pointers.h`, `src/xrCore/intrusive_ptr.h`
  - Что изучить: `xr_unique_ptr`, `xr_shared_ptr`, `intrusive_ptr`
  - Аналогия: как `useRef`, `useState` в React — автоматическое управление жизнью
  - Зачем: безопасность памяти, автоматическая очистка

- [ ] **Reference counting** (ref_sound, ref_light)
  - Файлы: `src/xrCore/xr_resource.h`
  - Что изучить: как работает подсчёт ссылок
  - Аналогия: как React отслеживает зависимости
  - Зачем: разделение ресурсов между объектами

### 0.2. Контейнеры данных (Data Structures)
- [ ] **xr_vector, xr_list, xr_map**
  - Файлы: `src/xrCommon/xr_vector.h`, `src/xrCommon/xr_list.h`, `src/xrCommon/xr_map.h`
  - Что изучить: кастомные обёртки над STL
  - Аналогия: как массивы/объекты в JS, но типизированные
  - Зачем: контроль над аллокацией, оптимизация

- [ ] **shared_str** — строки с подсчётом ссылок
  - Файлы: `src/xrCore/xrstring.h`
  - Что изучить: как работает `shared_str`
  - Аналогия: как строки в JS (immutable), но с явным подсчётом ссылок
  - Зачем: эффективное хранение строк, избежание копий

### 0.3. Базовые типы и утилиты
- [ ] **Математические типы** (Fvector, Fmatrix, Frect)
  - Файлы: `src/xrCore/_vector3d.h`, `src/xrCore/_matrix.h`, `src/xrCore/_rect.h`
  - Что изучить: векторы, матрицы, прямоугольники
  - Аналогия: как типы для работы с координатами в Canvas API
  - Зачем: 3D математика, геометрия

## 📋 Уровень 1: Архитектурные паттерны (Design Patterns)

**Сложность:** ⭐⭐  
**Время:** 3-5 дней  
**Цель:** Понять основные паттерны проектирования

### 1.1. Observer Pattern (MessageRegistry)
- [ ] **Система событий и последовательностей**
  - Файлы: `src/xrEngine/pure.h`, `src/xrEngine/device.h` (seqFrame, seqRender)
  - Что изучить: `MessageRegistry`, `pureFrame`, `pureRender`
  - Аналогия: как EventEmitter в Node.js или Context API в React
  - Зачем: слабая связанность, подписка на события кадра/рендеринга
  - **Практика:** Найти все места, где объекты регистрируются в seqFrame

### 1.2. Factory Pattern
- [ ] **Фабрика объектов** (FactoryObjectBase)
  - Файлы: `src/xrServerEntities/object_factory.h`
  - Что изучить: как создаются игровые объекты
  - Аналогия: как фабричные функции в JS
  - Зачем: централизованное создание объектов по типу

### 1.3. Component Pattern
- [ ] **Базовые компоненты объектов**
  - Файлы: `src/xrGame/GameObject.h`
  - Что изучить: `SpatialBase`, `ScheduledBase`, `RenderableBase`, `CollidableBase`
  - Аналогия: как компоненты в React (композиция вместо наследования)
  - Зачем: модульность, переиспользование кода

### 1.4. Singleton Pattern
- [ ] **Глобальные менеджеры** (Engine, Device, UI)
  - Файлы: `src/xrEngine/Engine.h`, `src/xrEngine/device.h`
  - Что изучить: `GEnv`, глобальные экземпляры
  - Аналогия: как глобальные контексты в React
  - Зачем: единая точка доступа к системам
