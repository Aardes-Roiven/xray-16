## 📖 Концептуальное объяснение

### Что это такое?

`shared_str` — это **строковый тип с подсчётом ссылок (reference counting)** и **интернированием строк (string interning)**. Это оптимизированная система для работы со строками в игровом движке.

**Простыми словами:** это умная строка, которая:
- Хранит одинаковые строки только один раз в памяти
- Позволяет делать дешёвые копии (копируется только указатель)
- Автоматически управляет памятью через подсчёт ссылок
- Обеспечивает быстрое сравнение строк (сравнение указателей вместо посимвольного)

### Где применяется?

`shared_str` используется повсеместно в движке для:

1. **Имена файлов и путей**
   - Загрузка ресурсов (текстуры, модели, звуки)
   - Пути к конфигурационным файлам
   - Имена уровней и локаций

2. **Секции конфигов**
   - Имена секций в `.ltx` файлах
   - Параметры игровых объектов
   - Настройки оружия, брони, артефактов

3. **Имена игровых объектов**
   - Типы объектов (`"actor"`, `"stalker"`, `"monster"`)
   - Классы оружия (`"wpn_ak74"`, `"wpn_pm"`)
   - Имена NPC и локаций

4. **UI система**
   - Имена UI элементов
   - Пути к текстурам интерфейса
   - Идентификаторы окон и диалогов

5. **Сетевые протоколы**
   - Идентификаторы команд
   - Имена игроков
   - События синхронизации

### Зачем это нужно?

#### Проблема обычных строк

В игре постоянно используются одни и те же строки:
- `"actor"` — тысячи раз
- `"wpn_ak74"` — сотни раз
- Имена секций конфигов — десятки тысяч раз

Если использовать обычные `std::string` или `char*`:
- ❌ Каждая копия строки занимает отдельную память
- ❌ Копирование строк медленное (нужно копировать все символы)
- ❌ Сравнение строк медленное (посимвольное сравнение)
- ❌ Много дублирования данных в памяти

#### Решение через `shared_str`

- ✅ **Одна физическая строка в памяти** — все `shared_str` с одинаковым содержимым указывают на один объект
- ✅ **Дешёвое копирование** — копируется только указатель (8 байт), а не вся строка
- ✅ **Быстрое сравнение** — сравнение указателей вместо посимвольного
- ✅ **Автоматическое управление памятью** — когда строка больше не нужна, она автоматически удаляется

**Аналогия:** Как строки в Python/Java (интернирование) + умные указатели в C++ (`std::shared_ptr`).

## 🔑 Ключевые концепции

### Интернирование строк (String Interning)

**Интернирование строк** — это техника оптимизации, при которой одинаковые строки хранятся в памяти один раз, а все ссылки указывают на этот единственный экземпляр.

#### Что это значит?

**БЕЗ интернирования:**
```
┌──────────┐
│  str1    │ ──→ "actor" (копия 1 в памяти)
└──────────┘

┌──────────┐
│  str2    │ ──→ "actor" (копия 2 в памяти) ❌ Дублирование!
└──────────┘

┌──────────┐
│  str3    │ ──→ "actor" (копия 3 в памяти) ❌ Дублирование!
└──────────┘

Итого: 3 копии строки "actor" в памяти
```

**С интернированием:**
```
┌──────────┐
│  str1    │ ──┐
└──────────┘   │
               │
┌──────────┐   │    ┌─────────────┐
│  str2    │ ──┼───→│  "actor"    │ ← Одна строка в памяти
└──────────┘   │    └─────────────┘
               │
┌──────────┐   │
│  str3    │ ──┘
└──────────┘

Итого: 1 строка "actor" в памяти, 3 указателя на неё ✅
```

#### Как это работает в `shared_str`?

В `shared_str` интернирование реализовано через `str_container`:

```cpp
// При создании shared_str из строки:
shared_str s1 = "actor";  // 1. Ищется "actor" в контейнере
                          // 2. Не найдена → создаётся и сохраняется
                          // 3. s1.p_ указывает на созданную строку

shared_str s2 = "actor";  // 1. Ищется "actor" в контейнере
                          // 2. Найдена! → возвращается существующая
                          // 3. s2.p_ указывает на ТУ ЖЕ строку, что и s1.p_

// s1.p_ == s2.p_  →  true! (один и тот же указатель)
```

#### Процесс интернирования в `dock()`:

```cpp
str_value* str_container::dock(pcstr value) const
{
    // 1. Вычисляем CRC32 для быстрого поиска
    sv->dwCRC = crc32(value, s_len);
    
    // 2. Ищем строку в хеш-таблице
    result = impl->find(sv, value);
    
    // 3. Если НЕ найдена → создаём новую (интернируем)
    if (nullptr == result)
    {
        result = static_cast<str_value*>(xr_malloc(...));
        // ... инициализация ...
        impl->insert(result);  // Сохраняем в контейнере
    }
    
    // 4. Возвращаем указатель (существующий или новый)
    return result;
}
```

#### Преимущества интернирования:

1. **Экономия памяти**
   - Одна строка хранится один раз, сколько бы ссылок ни было
   - Для часто используемых строк экономия значительна

2. **Быстрое сравнение**
   ```cpp
   // С интернированием:
   if (s1.p_ == s2.p_)  // O(1) - сравнение указателей
   
   // Без интернирования:
   if (strcmp(s1.c_str(), s2.c_str()) == 0)  // O(n) - посимвольное сравнение
   ```

3. **Дешёвое копирование**
   ```cpp
   shared_str s2 = s1;  // Копируется только указатель (8 байт)
                        // Не копируется вся строка!
   ```

#### Где используется интернирование:

- **Python** — все строки интернированы
- **Java** — строковые литералы интернированы
- **C#** — строки интернированы
- **XRay Engine** — через `shared_str`

#### Важные моменты:

1. **Строки неизменяемые (immutable)**
   - После интернирования содержимое не меняется
   - Это позволяет безопасно делить одну строку между объектами

2. **Подсчёт ссылок**
   - `dwReference` показывает, сколько `shared_str` ссылаются на строку
   - Когда счётчик становится 0, строка может быть удалена

3. **Глобальный контейнер**
   - Все интернированные строки хранятся в `g_pStringContainer`
   - Это singleton, доступный из любой части программы

### CRC32 — алгоритм хеширования

**CRC32** (Cyclic Redundancy Check, 32-bit) — это алгоритм вычисления контрольной суммы (хеша) для данных. Это 32-битное число, которое представляет содержимое данных.

#### Что это такое?

CRC32 — это "отпечаток" данных:
- Одинаковые данные → одинаковый CRC32
- Разные данные → (почти всегда) разный CRC32
- Быстро вычисляется
- Используется для быстрого поиска и проверки целостности

#### Примеры:

```cpp
CRC32("actor")   = 0x12345678  (пример)
CRC32("stalker") = 0xABCDEF01  (пример)
CRC32("actor")   = 0x12345678  (тот же результат!)
```

#### Зачем CRC32 в `shared_str`?

В методе `dock()` CRC32 используется так:

```cpp
// 1. Вычисляем CRC32 строки
sv->dwCRC = crc32(value, s_len);  // Например, "actor" → 0x12345678

// 2. Используем CRC для быстрого поиска в хеш-таблице
str_value* candidate = buffer[value->dwCRC % buffer_size];
// Индекс = 0x12345678 % 262144 = 12345
// Сразу переходим к buffer[12345], не проверяя все 262144 элемента!
```

**Преимущества:**
1. **Быстрый поиск** — сразу вычисляется индекс в хеш-таблице
2. **Быстрая предварительная проверка** — сначала сравниваем CRC, потом содержимое
3. **Эффективность** — O(1) для вычисления хеша

#### Реализация CRC32 в движке:

```cpp
u32 crc32(const void* P, u32 len)
{
    // Начальное значение
    u32 ulCRC = 0xffffffff;
    u8* buffer = (u8*)P;

    // Проходим по каждому байту данных
    while (len--)
        ulCRC = (ulCRC >> 8) ^ crc32_table[(ulCRC & 0xFF) ^ *buffer++];

    // Инвертируем результат
    return ulCRC ^ 0xffffffff;
}
```

#### Как работает алгоритм:

1. **Используется полином** `0x04c11db7` (стандартный для CRC32)
2. **Есть таблица из 256 значений** (lookup table) для ускорения
3. **Проходит по каждому байту данных** и обновляет CRC
4. **Возвращает 32-битное число** (от 0 до 0xFFFFFFFF)

#### Визуализация процесса:

```
Строка: "actor"
         ↓
    CRC32("actor")
         ↓
    0x12345678  (32-битное число)
         ↓
    Индекс = 0x12345678 % 262144 = 12345
         ↓
    Ищем в buffer[12345]
```

#### Важные особенности:

1. **Детерминированность** — одна и та же строка всегда даёт один и тот же CRC32
2. **Быстрота** — вычисление за O(n), где n — длина строки
3. **Коллизии возможны** — разные строки могут дать одинаковый CRC32 (редко)
4. **Необратимость** — по CRC32 нельзя восстановить исходную строку

#### Где ещё используется CRC32 в движке:

- Проверка целостности файлов
- Синхронизация сетевых данных
- Кэширование ресурсов
- Проверка изменений конфигураций

#### Связь интернирования и CRC32:

CRC32 и интернирование работают вместе:

1. **CRC32** используется для быстрого поиска строки в хеш-таблице
2. **Интернирование** обеспечивает, что одинаковые строки хранятся один раз
3. Вместе они дают эффективную систему хранения и поиска строк

```
Строка "actor"
     ↓
CRC32 → 0x12345678
     ↓
Индекс в хеш-таблице → 12345
     ↓
Поиск в buffer[12345]
     ↓
Найдена? → Да → Возвращаем существующую (интернирование работает!)
         → Нет → Создаём новую и сохраняем
```

```

├─ buffer[2] ──→ null
│
├─ buffer[12345] ──→ str_value { CRC=0x1234, value="actor" }
│                     │
│                     └─→ next ──→ str_value { CRC=0x1234, value="actor2" }
│                                   │
│                                   └─→ next ──→ null
│
├─ buffer[67890] ──→ str_value { CRC=0x5678, value="wpn_ak74" }
│                     │
│                     └─→ next ──→ null
│
└─ buffer[262143] ──→ null

Поиск строки "actor":
1. CRC32("actor") = 0x12345678
2. Индекс = 0x12345678 % 262144 = 12345
3. Проходим по цепочке buffer[12345]:
   - Проверяем первый: CRC совпадает? Длина совпадает? Содержимое совпадает?
   - Если нет → следующий элемент
   - Если да → возвращаем указатель
```

## 🔍 Разбор кода

### 1. Структура `str_value` — хранилище строки

```cpp
struct XRCORE_API str_value
{
    u32 dwReference;      // Счётчик ссылок
    u32 dwLength;         // Длина строки (без \0)
    u32 dwCRC;            // CRC32 для быстрого поиска
    str_value* next;      // Указатель для хеш-таблицы (цепочка коллизий)
    char value[];         // Гибкий массив с данными строки
};
```

**Что здесь происходит:**

- **`dwReference`** — счётчик ссылок. Показывает, сколько `shared_str` указывают на эту строку
- **`dwLength`** — длина строки без завершающего нуля
- **`dwCRC`** — CRC32 хеш строки. Используется для быстрого поиска в хеш-таблице
- **`next`** — указатель на следующий элемент в цепочке коллизий хеш-таблицы
- **`char value[]`** — это **Flexible Array Member** (FAM). Это не указатель, а массив переменной длины в конце структуры

**Важно:** `char value[]` — это массив переменной длины. Память выделяется так:
```cpp
xr_malloc(sizeof(str_value) + длина_строки + 1)
```

### 2. Класс `shared_str` — обёртка над `str_value`

#### Внутреннее устройство

```cpp
class shared_str
{
    str_value* p_{};  // Указатель на str_value (может быть nullptr)
    
    // ... методы ...
};
```

`shared_str` хранит только один указатель на `str_value`. Вся магия в методах!

#### Ключевые методы

##### `_dec()` — уменьшение счётчика ссылок

```cpp
void _dec() noexcept
{
    if (nullptr == p_)
        return;
    p_->dwReference--;
    if (0 == p_->dwReference)
        p_ = nullptr;
}
```

**Что делает:**
- Уменьшает счётчик ссылок на 1
- Если счётчик стал 0, обнуляет указатель
- **Важно:** сама строка не удаляется здесь! Удаление происходит в `str_container::clean()`

##### `_set(pcstr rhs)` — установка из C-строки

```cpp
void _set(pcstr rhs)
{
    str_value* v = g_pStringContainer->dock(rhs);  // Найти или создать str_value
    if (nullptr != v)
        v->dwReference++;  // Увеличить счётчик
    _dec();  // Уменьшить счётчик старой строки
    p_ = v;  // Сохранить новый указатель
}
```

**Алгоритм:**
1. Вызывает `g_pStringContainer->dock(rhs)` — ищет строку в контейнере или создаёт новую
2. Увеличивает счётчик найденной/созданной строки
3. Уменьшает счётчик старой строки (если была)
4. Сохраняет новый указатель

##### `_set(shared_str const& rhs)` — копирование

```cpp
void _set(shared_str const& rhs) noexcept
{
    str_value* v = rhs.p_;
    if (nullptr != v)
        v->dwReference++;  // Увеличить счётчик
    _dec();  // Уменьшить счётчик старой строки
    p_ = v;  // Сохранить указатель
}
```

**Это и есть дешёвое копирование!** Копируется только указатель, а не сама строка.

#### Конструкторы

```cpp
// Конструктор по умолчанию
shared_str() = default;  // p_ = nullptr

// Конструктор из C-строки
shared_str(pcstr rhs)
{
    p_ = nullptr;
    _set(rhs);  // Найти или создать str_value
}

// Конструктор копирования
shared_str(shared_str const& rhs) noexcept
{
    p_ = nullptr;
    _set(rhs);  // Увеличить счётчик
}

// Конструктор перемещения (C++11)
shared_str(shared_str&& rhs) noexcept
    : p_(rhs.p_)
{
    rhs.p_ = nullptr;  // Забрать указатель, не увеличивая счётчик
}
```

**Важно:** Конструктор перемещения не изменяет счётчик ссылок — это оптимизация!

#### Деструктор

```cpp
~shared_str() { _dec(); }
```

При уничтожении `shared_str` уменьшается счётчик ссылок.

#### Операторы присваивания

```cpp
shared_str& operator=(pcstr rhs)
{
    _set(rhs);
    return *this;
}

shared_str& operator=(shared_str const& rhs) noexcept
{
    _set(rhs);
    return *this;
}

shared_str& operator=(shared_str&& rhs) noexcept
{
    p_ = rhs.p_;
    rhs.p_ = nullptr;
    return *this;
}
```

#### Методы доступа

```cpp
// Получить C-строку
pcstr c_str() const { return p_ ? p_->value : nullptr; }

// Оператор разыменования (небезопасный, помечен как опасный)
pcstr operator*() const { return p_ ? p_->value : nullptr; }

// Проверка на пустоту
bool operator!() const { return p_ == nullptr; }

// Доступ к символу по индексу
char operator[](size_t id) { return p_->value[id]; }
char operator[](size_t id) const { return p_->value[id]; }

// Размер строки
size_t size() const
{
    if (nullptr == p_)
        return 0;
    return p_->dwLength;
}

bool empty() const { return size() == 0; }
```

#### Операторы сравнения

```cpp
IC bool operator==(shared_str const& a, shared_str const& b) 
{ 
    return a._get() == b._get();  // Сравнение указателей!
}

IC bool operator!=(shared_str const& a, shared_str const& b) 
{ 
    return a._get() != b._get(); 
}
```

**Ключевой момент:** Сравнение происходит по указателям! Если две строки интернированы (одинаковое содержимое), они имеют один и тот же указатель, поэтому сравнение очень быстрое.

#### Специальные методы

```cpp
// Обмен значениями
void swap(shared_str& rhs) noexcept
{
    str_value* tmp = p_;
    p_ = rhs.p_;
    rhs.p_ = tmp;
}

// Проверка на равенство (по указателям)
bool equal(const shared_str& rhs) const 
{ 
    return (p_ == rhs.p_); 
}

// Форматирование строки (как sprintf)
shared_str& printf(const char* format, ...)
{
    string4096 buf;
    va_list p;
    va_start(p, format);
    int vs_sz = vsnprintf(buf, sizeof(buf) - 1, format, p);
    buf[sizeof(buf) - 1] = 0;
    va_end(p);
    if (vs_sz)
        _set(buf);
    return *this;
}
```

### 3. `str_container` — хранилище всех строк

```cpp
class XRCORE_API str_container
{
public:
    str_container();
    ~str_container();

    str_value* dock(pcstr value) const;  // Найти или создать строку
    void clean() const;                  // Удалить неиспользуемые строки
    void dump() const;                   // Вывести все строки в файл
    void verify() const;                 // Проверить целостность

    std::pair<size_t, size_t> stat_economy() const;  // Статистика экономии памяти

private:
    str_container_impl* impl;
};

XRCORE_API extern str_container* g_pStringContainer;  // Глобальный экземпляр
```

`g_pStringContainer` — это **глобальный singleton**, который хранит все строки движка.

### 4. Реализация `str_container_impl` — хеш-таблица

```cpp
struct str_container_impl
{
    Lock cs;  // Мьютекс для потокобезопасности
    static constexpr size_t buffer_size = 1024u * 256u;  // 262144 (256K)
    str_value* buffer[buffer_size];  // Хеш-таблица
    int num_docs;
    
    // ... методы ...
};
```

**Структура данных:**
- **`buffer[262144]`** — массив указателей (хеш-таблица)
- **`Lock cs`** — мьютекс для защиты от гонок данных в многопоточности
- Размер таблицы: 256K элементов

#### Метод `find()` — поиск строки

```cpp
str_value* find(str_value* value, const char* str) const
{
    // Вычисляем индекс в хеш-таблице по CRC
    str_value* candidate = buffer[value->dwCRC % buffer_size];
    
    // Проходим по цепочке коллизий
    while (candidate)
    {
        // Проверяем: CRC, длину и содержимое
        if (candidate->dwCRC == value->dwCRC && 
            candidate->dwLength == value->dwLength &&
            !memcmp(candidate->value, str, value->dwLength))
        {
            return candidate;  // Нашли!
        }
        candidate = candidate->next;
    }
    
    return nullptr;  // Не нашли
}
```

**Алгоритм поиска:**
1. Вычисляет индекс: `CRC % buffer_size`
2. Проходит по цепочке коллизий
3. Сравнивает CRC, длину и содержимое
4. Возвращает найденную строку или `nullptr`

#### Метод `insert()` — вставка строки

```cpp
void insert(str_value* value)
{
    str_value** element = &buffer[value->dwCRC % buffer_size];
    value->next = *element;  // Вставляем в начало цепочки
    *element = value;
}
```

Вставка происходит в начало цепочки коллизий (простая и быстрая операция).

#### Метод `clean()` — очистка неиспользуемых строк

```cpp
void clean()
{
    for (size_t i = 0; i < buffer_size; ++i)
    {
        str_value** current = &buffer[i];
        
        while (*current != nullptr)
        {
            str_value* value = *current;
            if (!value->dwReference)  // Счётчик ссылок = 0
            {
                *current = value->next;  // Удаляем из цепочки
                xr_free(value);          // Освобождаем память
            }
            else
            {
                current = &value->next;  // Переходим к следующему
            }
        }
    }
}
```

**Важно:** Удаляются только строки с `dwReference == 0` (никто на них не ссылается).

### 5. Метод `dock()` — главный метод поиска/создания строки

```cpp
str_value* str_container::dock(pcstr value) const
{
    if (nullptr == value)
        return nullptr;

    impl->cs.Enter();  // Блокируем мьютекс

    str_value* result = nullptr;

    // 1. Вычисляем длину строки
    const auto s_len = xr_strlen(value);
    const auto s_len_with_zero = s_len + 1;
    VERIFY(sizeof(str_value) + s_len_with_zero < 4096);

    // 2. Создаём временную структуру для поиска
    char header[sizeof(str_value)];
    str_value* sv = (str_value*)header;
    sv->dwReference = 0;
    sv->dwLength = static_cast<u32>(s_len);
    sv->dwCRC = crc32(value, s_len);  // Вычисляем CRC32

    // 3. Ищем строку в хеш-таблице
    result = impl->find(sv, value);

    // 4. Если не нашли — создаём новую
    if (nullptr == result)
    {
        // Выделяем память: структура + строка + \0
        result = static_cast<str_value*>(
            xr_malloc(sizeof(str_value) + s_len_with_zero)
        );

        // Инициализируем структуру
        result->dwReference = 0;
        result->dwLength = sv->dwLength;
        result->dwCRC = sv->dwCRC;
        CopyMemory(result->value, value, s_len_with_zero);

        // Вставляем в хеш-таблицу
        impl->insert(result);
    }
    
    impl->cs.Leave();  // Разблокируем мьютекс
    return result;
}
```

**Алгоритм работы:**

1. **Блокировка мьютекса** — защита от гонок данных
2. **Вычисление CRC32** — для быстрого поиска
3. **Поиск в хеш-таблице** — по CRC, длине и содержимому
4. **Создание новой строки** (если не найдена):
   - Выделение памяти: `sizeof(str_value) + длина_строки + 1`
   - Копирование строки
   - Вставка в хеш-таблицу
5. **Разблокировка мьютекса**
6. **Возврат указателя** на `str_value`

## ⚡ Преимущества и особенности

### Преимущества

1. **Экономия памяти**
   - Одна строка хранится один раз, сколько бы копий ни было
   - Метод `stat_economy()` показывает, сколько памяти сэкономлено

2. **Быстрое копирование**
   - Копируется только указатель (8 байт на 64-bit системе)
   - Не зависит от длины строки

3. **Быстрое сравнение**
   - Сравнение указателей вместо посимвольного
   - O(1) вместо O(n)

4. **Потокобезопасность**
   - Мьютекс защищает операции с `str_container`
   - Можно безопасно использовать из разных потоков

5. **Автоматическая очистка**
   - Метод `clean()` удаляет неиспользуемые строки
   - Не нужно вручную управлять памятью

### Особенности

1. **Строки неизменяемые (immutable)**
   - Нельзя изменить содержимое `shared_str`
   - При "изменении" создаётся новая строка

2. **Сравнение по указателям**
   - `operator==` сравнивает указатели, а не содержимое
   - Если строки интернированы, это работает правильно
   - Если нужно посимвольное сравнение, используйте `xr_strcmp()`

3. **Глобальный контейнер**
   - Все строки хранятся в `g_pStringContainer`
   - Это singleton, создаётся при инициализации движка

4. **CRC32 для поиска**
   - Используется для быстрого поиска в хеш-таблице
   - Возможны коллизии (обрабатываются через цепочки)

## 🔧 Внутренние детали

### Жизненный цикл строки

1. **Создание:**
   ```cpp
   shared_str s = "hello";
   // 1. Вызывается dock("hello")
   // 2. Ищется в хеш-таблице
   // 3. Если не найдена - создаётся новый str_value
   // 4. dwReference = 1
   ```

2. **Копирование:**
   ```cpp
   shared_str s2 = s;
   // 1. Копируется указатель p_
   // 2. dwReference++ (теперь = 2)
   ```

3. **Уничтожение:**
   ```cpp
   s2.~shared_str();
   // 1. Вызывается _dec()
   // 2. dwReference-- (теперь = 1)
   // 3. Указатель обнуляется
   ```

4. **Очистка:**
   ```cpp
   str_container::clean();
   // 1. Проходит по всем строкам
   // 2. Удаляет строки с dwReference == 0
   ```

### Хеш-таблица

- **Размер:** 262144 (256K) элементов
- **Хеш-функция:** `CRC32 % buffer_size`
- **Разрешение коллизий:** цепочки (chaining)
- **Вставка:** O(1) в среднем
- **Поиск:** O(1) в среднем, O(n) в худшем случае

### Потокобезопасность

- Все операции с `str_container` защищены мьютексом
- Операции с `shared_str` (копирование, присваивание) не требуют блокировки
- Только `dock()` и `clean()` требуют синхронизации
