# Чеклист: Архитектура игрового цикла OpenXRay

## Уровень 1: Общая картина (контекст)

- [ ] 1.1. Объяснить, что такое игровой цикл
  - Бесконечный цикл, который выполняется пока игра работает
  - Каждая итерация = один кадр (frame)
  - Цель: обновить логику → отрисовать → повторить

- [ ] 1.2. Показать точку входа
  - `CApplication::Run()` — главный цикл приложения
  - Файл: `src/xrEngine/x_ray.cpp:367`
  - `while (!SDL_QuitRequested())` — работает пока не закрыли окно

## Уровень 2: Структура одного кадра (что происходит за итерацию)

- [ ] 2.1. Обработка событий (Events)
  - События SDL (окно, мышь, клавиатура)
  - `SDL_PeepEvents()` — получение событий
  - `Device.ProcessEvent()` — обработка каждого события
  - Примеры: изменение размера окна, фокус, закрытие

- [ ] 2.2. Обработка кадра (ProcessFrame)
  - `Device.ProcessFrame()` — основной метод кадра
  - Файл: `src/xrEngine/device.cpp:261`
  - Внутри: обновление → рендеринг → синхронизация

## Уровень 3: Обновление логики (Update Phase)

- [ ] 3.1. Обновление времени (FrameMove)
  - `FrameMove()` — подготовка времени для кадра
  - `dwFrame++` — счётчик кадров
  - `fTimeDelta` — время между кадрами (для физики/анимаций)
  - `dwTimeGlobal` — глобальное время игры
  - Режимы: постоянный FPS или переменный

- [ ] 3.2. Система последовательностей (MessageRegistry)
  - Что это: список объектов, которые нужно обновить
  - Приоритеты: HIGH → NORMAL → LOW
  - `seqFrame.Process()` — вызывает `OnFrame()` у всех зарегистрированных объектов
  - Аналогия: очередь задач с приоритетами

- [ ] 3.3. Что обновляется в seqFrame
  - `CEngine::OnFrame()` — события движка (приоритет HIGH+1000)
  - `IGame_Persistent::OnFrame()` — персистентная игровая логика (HIGH+1)
  - `IGame_Level::OnFrame()` — уровень и объекты
  - `CSheduler::Update()` — планировщик игровых объектов
  - `CDialogHolder::OnFrame()` — UI диалоги
  - Порядок: по приоритету (от высокого к низкому)

## Уровень 4: Планировщик (Sheduler) — как обновляются объекты

- [ ] 4.1. Что такое Sheduler
  - Планировщик обновления игровых объектов
  - Два типа: Realtime (каждый кадр) и Scheduled (по расписанию)
  - `Objects.Update()` — обновление всех объектов уровня

- [ ] 4.2. Как работает обновление объектов
  - Каждый объект реализует `shedule_Update(dt)`
  - `dt` — время с последнего обновления
  - Объекты могут регистрироваться/отменяться динамически

## Уровень 5: Рендеринг (Render Phase)

- [ ] 5.1. Когда происходит рендеринг
  - После обновления логики
  - `DoRender()` — метод рендеринга
  - `seqRender.Process()` — вызывает `OnRender()` у всех зарегистрированных

- [ ] 5.2. Что рендерится
  - `IGame_Level::OnRender()` — рендеринг уровня
  - `GEnv.Render->Calculate()` — расчёт видимости
  - `GEnv.Render->Render()` — отрисовка
  - ImGui — отладочный интерфейс
  - `RenderEnd()` — Present (показ кадра на экране)

## Уровень 6: Многопоточность (Parallel Processing)

- [ ] 6.1. Параллельные задачи
  - `seqParallel` — список задач для параллельного выполнения
  - `seqFrameMT` — многопоточное обновление (например, звук)
  - Запуск через `TaskScheduler->AddTask()`
  - Ожидание через `TaskScheduler->Wait()`

- [ ] 6.2. Зачем это нужно
  - Основной поток: логика + рендеринг
  - Фоновые потоки: звук, физика, загрузка
  - Улучшает производительность

## Уровень 7: Синхронизация и ограничение FPS

- [ ] 7.1. Контроль частоты кадров
  - `ps_fps_limit` — лимит FPS
  - `ps_fps_limit_in_menu` — лимит в меню
  - Если кадр быстрый → `Sleep()` для синхронизации

- [ ] 7.2. Режимы работы
  - Обычный режим: переменный FPS
  - Постоянный FPS: `rsConstantFPS` (30 или 50 FPS)
  - Пауза: `fTimeDelta = 0.0f`

## Уровень 8: Детали реализации (для углубления)

- [ ] 8.1. MessageRegistry — как работает
  - Хранит список объектов с приоритетами
  - `Add()` — регистрация объекта
  - `Process()` — вызов всех `OnPure()` по приоритету
  - `Remove()` — удаление (помечает как INVALID)

- [ ] 8.2. Интерфейсы pureFrame, pureRender
  - `pureFrame` — объекты, обновляющиеся каждый кадр
  - `pureRender` — объекты, которые рендерятся
  - Объект может быть и тем, и другим

- [ ] 8.3. Жизненный цикл объектов
  - Регистрация: `Device.seqFrame.Add(this, priority)`
  - Обновление: автоматически каждый кадр
  - Удаление: `Device.seqFrame.Remove(this)`

## Уровень 9: Практические примеры

- [ ] 9.1. Пример: как объект попадает в цикл
  - Создание объекта → регистрация в seqFrame → автоматическое обновление
  - Пример: `IGame_Level` регистрируется при загрузке уровня

- [ ] 9.2. Пример: порядок обновления
  - Engine (события) → GamePersistent → Level → Objects → UI
  - Рендеринг: Level → UI → Debug

- [ ] 9.3. Пример: обработка паузы
  - `Device.Paused()` → `fTimeDelta = 0.0f`
  - Обновление продолжается, но время не идёт
  - Рендеринг продолжается (видим застывшую картинку)

## Уровень 10: Визуализация потока данных

- [ ] 10.1. Схема одного кадра
  ```
  SDL Events → ProcessEvent()
       ↓
  ProcessFrame()
       ↓
  FrameMove() → seqFrame.Process() → [Engine → GamePersistent → Level → Sheduler → UI]
       ↓
  OnCameraUpdated()
       ↓
  [Параллельно] seqParallel + seqFrameMT
       ↓
  DoRender() → seqRender.Process() → [Level Render → UI Render → ImGui]
       ↓
  Wait(parallel tasks)
       ↓
  Sleep(если нужно ограничить FPS)
  ```

  - `src/xrEngine/pure.h:28` — MessageRegistry
